Core includes to KEEP: JSON headers, Editor.h

Reflection conversion approach:
- All 4 handlers: first check MCPReflect::CheckModuleLoaded(TEXT("LiveLinkInterface")). If false, return module_not_available.
- The .disabled file accesses ILiveLinkClient via IModularFeatures::Get().GetModularFeature<ILiveLinkClient>. Since we cannot include the ILiveLinkClient header, instead: use FindObject<UClass>(nullptr, TEXT("/Script/LiveLinkInterface.LiveLinkClient")) or check if the modular feature is registered by name. The IModularFeatures header is from Core module and CAN be included. Use IModularFeatures::Get().IsModularFeatureAvailable(TEXT("LiveLinkClient")) to check availability, then use IModularFeatures::Get().GetModularFeature<IModularFeature>(TEXT("LiveLinkClient")) cast to UObject* if possible. However, ILiveLinkClient is NOT a UObject -- it is a C++ interface inheriting from IModularFeature.
- Alternative approach: Since LiveLink types are not UObjects, use a subsystem-based approach instead. Check for ULiveLinkSubsystem via FindObject<UClass>(nullptr, TEXT("/Script/LiveLink.LiveLinkSubsystem")) and get it from GEditor. If the class is found, use reflection (TFieldIterator<FProperty>) to enumerate subjects and sources. Use FindFunction + ProcessEvent to call methods like GetSubjects(), GetSources().
- For subject data: Use FindObject<UScriptStruct> to find FLiveLinkSubjectKey, FLiveLinkSubjectFrameData structs by path. Read properties via reflection.
- For role names: Instead of casting to specific role classes (LiveLinkAnimationRole etc.), read the role class name from the subject as a string via reflection -- the UClass name contains the role type.
- livelink.control (pause/resume): Find UFunction by name on the subsystem (like SetSubjectEnabled or similar) and call via ProcessEvent.
- livelink.preview: Read current frame data via reflection on the subject frame struct.

Create .h identical to .disabled (register function declaration only).
